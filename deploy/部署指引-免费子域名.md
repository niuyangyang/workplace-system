# 部署到免费静态托管（拿到正式感域名）

> 部署包：`deploy/dist-2026-10-08.zip`（4.73MB，站点文件在压缩包根目录，可直接上传）
> 版本口径：与当前线上一致的构建产物（含「员工订餐 H5 单形态」、已隐藏 4 个应用入口）
> 目标：把 `xxxxx.app.workbuddy.host` 这种随机哈希地址，换成 `xxx.netlify.app` / `xxx.pages.dev` 这类正式感地址

---

## 路线 A1 · Netlify（最快，推荐先试）

1. 打开 https://app.netlify.com/drop
2. 把 `deploy/dist-2026-10-08.zip` **直接拖进页面**（或拖 `dist` 文件夹）
3. 等约 30 秒，页面上出现一个临时地址（形如 `random-name-123.netlify.app`）——此时站点已经能访问
4. 想换成自己起的名字：Site configuration（站点配置）→ **Change site name** → 填 `workplace-hub` 之类 → 地址变成 `workplace-hub.netlify.app`
   - 名字只能用小写字母、数字和连字符，且全局唯一；被占用就换一个
5. 建议同时设置：Site configuration → Build & deploy → **Deploy log** 无需管；如要防止别人误删，可在 Team settings 里开启两步验证

## 路线 A2 · Cloudflare Pages（国内访问通常更稳）

1. 打开 https://dash.cloudflare.com → 左侧 **Workers & Pages** → **Create** → 选 **Pages** → **Upload assets**
2. 项目名填 `workplace-hub`（这会成为子域名 → `workplace-hub.pages.dev`）
3. 把 `deploy/dist-2026-10-08.zip` 拖进上传区（或拖 `dist` 文件夹）→ **Deploy site**
4. 约 30 秒后拿到 `https://workplace-hub.pages.dev`

> 两个平台都免费、都自带 HTTPS，任选其一即可；也可以两个都传一份，简历上放主力那个。

---

## 关键注意点

- **深链不要漏**：包内已包含 `404.html`（与 `index.html` 同内容）。Netlify 与 Cloudflare Pages 在访问不存在的路径时会返回 `404.html`，单页应用的深链（如 `/app/meal`）因此能正常打开。**如果你手动只上传了 index.html 而漏了 404.html，刷新子页面会 404。**
- **不要上传整个项目**：只传 `dist`（或这个 zip）。项目源码、`node_modules`、`.workbuddy` 都不需要上传。
- **中文文件名**：包内没有中文文件名，可放心上传。

## 后续可选：绑定自己的域名（路线 B）

1. 买域名（约 ¥60-100/年）：国内可在阿里云/腾讯云买（`.com`/`.cn`），国外可在 Cloudflare Registrar / Namecheap 买（`.dev`/`.me`/`.com`）
2. 在 Netlify / Cloudflare Pages 项目里 → **Custom domains** → 添加域名（如 `hub.yourname.dev`）
3. 按平台提示在域名商处添加 DNS 记录：
   - Netlify：加 `CNAME`，主机记录填 `hub`，记录值填你的 `xxx.netlify.app`
   - Cloudflare Pages：如果域名也托管在 Cloudflare，一键即可；否则加 `CNAME` 指向 `xxx.pages.dev`
4. 等待几分钟生效，HTTPS 证书由平台自动签发
5. 注意：**托管在境外的平台不需要 ICP 备案**；若改用国内云（OSS/COS + CDN），自定义域名必须先完成 ICP 备案（需主体资质，约 1-2 周）

## 以后如何更新线上版本

源码改动后，在项目目录执行（PowerShell 或 Git Bash）：

```bash
# 1. 重新构建（注意：本项目构建需先清除 6 个 safe-delete 环境变量，否则会被拦截）
npm run build

# 2. 补上深链回退文件
cp dist/index.html dist/404.html

# 3. 重新打包
```

打包可复用本目录的思路：把 `dist` 内的文件压成 zip（站点文件放压缩包根目录，不要多一层 `dist/`）。

然后回到 Netlify / Cloudflare Pages 项目里重新上传一次即可（Netlify 也支持在 Deploys 页面把新 zip 拖进去，旧版本自动保留可回滚）。

> 需要重新构建+打包时，直接把需求告诉我，我执行完把新的 zip 放到 `deploy/` 下给你。
